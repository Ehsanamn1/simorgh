# توسعهٔ بدون دیتابیس و انتقال به هاست

این راهنما تصمیم فعلی استقرار مدار را مشخص می‌کند: توسعهٔ UI/UX و منطق کلاینت در حالت مستقل از دیتابیس ادامه می‌یابد؛ سورس بک‌اند و migrationها حفظ می‌شوند؛ اتصال عملیاتی تا زمان تعیین سازگاری هاست خریداری‌شده فعال نمی‌شود.

## حالت‌های اجرا

### ۱. نمایش استاتیک (بدون API و دیتابیس)

برای ساخت نسخهٔ معرفی GitHub Pages:

```bash
npm install
VITE_ENABLE_AUTH_UI=false VITE_DISABLE_API_UI=true npm run build:pages
```

در PowerShell:

```powershell
$env:VITE_ENABLE_AUTH_UI="false"
$env:VITE_DISABLE_API_UI="true"
npm run build:pages
```

این حالت برای ظاهر، واکنش‌گرایی و نمایش جریان‌های نمایشی است. داده‌ها نمونه‌اند؛ ورود، حساب‌های واقعی، ذخیرهٔ مشترک و عملیات تجاری پایدار ارائه نمی‌شود. اطلاعات حساس یا واقعی را در آن وارد نکنید.

### ۲. توسعهٔ عملیاتی محلی

حالت عملیاتی کلاینت به API نیاز دارد. برای اجرای بک‌اند فعلی محلی، Node.js 22+ و یک PostgreSQL سازگار لازم است؛ پیکربندی Worker در `worker/wrangler.toml` و مهاجرت‌ها در `worker/migrations/` هستند. متغیر `DATABASE_URL` فقط در محیط سرور/Worker قرار می‌گیرد و هرگز نباید با پیشوند `VITE_` در مرورگر منتشر شود.

تا وقتی دیتابیس توسعه آماده نیست، UI را در حالت استاتیک اجرا کنید و منطق کلاینت را با تست‌های واحد/مرورگر و داده‌های نمونه بررسی کنید. حالت استاتیک را محیط عملیاتی یا جایگزین دیتابیس در نظر نگیرید.

## وضعیت فعلی و محدودیت مهم

- فرانت‌اند: React + TypeScript + Vite؛ وب و پوسته‌های Capacitor از کد مشترک استفاده می‌کنند.
- API فعلی: Hono روی Cloudflare Workers.
- دیتابیس فعلی: PostgreSQL از طریق Neon Serverless؛ migrationهای SQL موجود در `worker/migrations/` برای PostgreSQL نوشته شده‌اند.
- رابط دادهٔ فرانت‌اند از API مدار عبور می‌کند؛ اتصال مستقیم مرورگر به دیتابیس وجود ندارد.
- انتشار خودکار Cloudflare در دورهٔ توسعهٔ استاتیک غیرفعال است؛ workflow موجود را می‌توان دستی اجرا کرد.
- این مخزن هنوز بک‌اند مستقل از پلتفرم برای همهٔ هاست‌ها ندارد. کپی ZIP به هاست PHP/MySQL به‌تنهایی API فعلی را اجرا نمی‌کند.

## روند انتقال امن به هاست

۱. مشخصات واقعی هاست را بررسی کنید: اجرای Node.js و نسخهٔ آن، امکان اجرای فرایند/اپلیکیشن دائمی یا serverless، نسخه و نوع دیتابیس، دسترسی شبکه به دیتابیس، SSL، متغیرهای محیطی، محدودیت حافظه/CPU و روش انتشار.

۲. یکی از دو مسیر را انتخاب کنید:
- **هاست Node.js + PostgreSQL:** کم‌تغییرترین مسیر برای حفظ API و schema فعلی است؛ ممکن است نیاز به تطبیق لایهٔ اجرا، کوکی/دامنه، فایل‌ها و زمان‌بندی‌ها داشته باشد.
- **هاست PHP + MySQL/MariaDB یا PostgreSQL در محیط محدود:** لازم است API با محیط هاست سازگار شود و در صورت MySQL، SQL، انواع داده، تراکنش‌ها، قفل‌گذاری، توابع و migrationها به‌صورت مهندسی‌شده منتقل شوند. این کار با تغییر یک URL انجام نمی‌شود.

۳. محیط staging جدا از تولید بسازید. هیچ migration روی دیتابیس دارای داده بدون backup قابل‌بازیابی، بررسی سازگاری و برنامهٔ rollback اجرا نشود.

۴. secrets را در پنل هاست ثبت کنید؛ فایل `.env` واقعی و گذرواژه‌ها را در Git یا ZIP عمومی قرار ندهید.

۵. نصب/استقرار باید پس از بررسی اتصال، migrationهای pending را با ثبت نسخه و checksum اجرا کند؛ migrationها باید قابل تکرار و افزایشی باشند. سپس سلامت API، ورود، نقش‌ها، مجوزهای رکوردی، ذخیره/خواندن داده و مسیرهای مستقیم را smoke-test کند.

۶. انتقال دادهٔ واقعی مرحله‌ای و جدا از migration schema است: backup منبع، نگاشت schema، import، تطبیق شمار رکوردها و کلیدهای خارجی، تست نمونه‌ها، سپس تغییر ترافیک. این فرایند نباید با ساخت دیتابیس خالی یا اجرای migrationها ادعا کند که داده‌های قبلی منتقل شده‌اند.

## تعریف «راه‌اندازی خودکار»

هدف نهایی یک دستور نصب/استقرار قابل تکرار است که پس از تنظیم امن متغیرهای محیطی:
- اتصال دیتابیس را بررسی کند؛
- migrationهای نسخه‌بندی‌شده و سازگار را اجرا کند؛
- وضعیت schema را ثبت کند؛
- health check و smoke test را اجرا کند؛
- در صورت شکست، انتشار را ناموفق اعلام کند و به‌طور خودکار دادهٔ تولیدی را حذف نکند.

ساخت حساب مالک اولیه باید از مسیر کنترل‌شده و امن انجام شود؛ گذرواژهٔ پیش‌فرض یا حساب عمومی ثابت نباید در سورس قرار گیرد.

## معیار تکمیل پیش از انتشار واقعی

- [ ] محیط staging و دیتابیس جداگانه
- [ ] backup و روش بازیابی آزمایش‌شده
- [ ] تمام migrationها روی نسخهٔ دقیق دیتابیس هدف اجرا شده‌اند
- [ ] احراز هویت و نقش‌های مالک/مدیر/تأمین‌کننده/راننده تست شده‌اند
- [ ] تست منفی دسترسی به رکورد شرکت دیگر موفق است
- [ ] ایجاد/ویرایش/خواندن داده از API واقعی موفق است
- [ ] مسیرهای فایل، CORS، کوکی امن، HTTPS و دامنه بررسی شده‌اند
- [ ] انتقال داده با شمارش و تطبیق رکوردها تأیید شده است
- [ ] بستهٔ ZIP با manifest نسخه و راهنمای نصب تولید شده است

**وضعیت:** حالت استاتیک و خروجی ZIP برای توسعه/نمایش آماده‌سازی شده‌اند؛ سازگاری نهایی با هاست خریداری‌شده و انتقال دیتابیس تا بررسی مشخصات واقعی هاست انجام‌شده محسوب نمی‌شوند.
