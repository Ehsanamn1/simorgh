# Simorgh native mobile app

Simorgh is now configured for Android and iOS packaging with Capacitor. The operational UI is shared from the React application, while Android/iOS projects are generated by Capacitor and use bundled assets from `dist/`; this is not a PWA-only delivery plan.

## Build an Android test APK

The `Simorgh Android App` GitHub Actions workflow builds an unsigned debug APK on pull requests, pushes to `main`, or manual dispatch. Download the artifact named `simorgh-android-debug-apk` from the completed workflow run and sideload it on an Android test device. Debug builds are for internal validation, not Play Store release.

Local setup requires Node.js 22+, Android Studio, and Android SDK API 36:

```sh
npm install
npm run build
npx cap add android
npx cap sync android
npx cap open android
```

The iOS target is declared as a dependency; creating/running an iOS app requires macOS and Xcode. The simulator workflow includes the iOS location permission description for foreground-only GPS capture:

```sh
npm install
npm run build
npx cap add ios
npx cap sync ios
npx cap open ios
```

## Release constraints

- The GitHub Actions artifact is a debug APK and is not signed for public distribution.
- Google Play publication requires a protected release keystore and store credentials.
- Installation on a physical iPhone/TestFlight requires Apple signing, a developer team, and provisioning.
- Never commit signing keys, Apple credentials, service-role keys, or production secrets.
- Supabase still enforces authentication and database authorization. The mobile shell must not bypass RLS to make the app appear open.

## App behavior

- App launch goes directly to the operational route; no marketing page or public self-registration is part of the entry flow.
- A fresh device must sign in using an account provisioned by the company owner.
- Theme selection is saved locally as a user interface preference; it does not alter roles or backend data.
- Native GPS, push notifications, barcode/QR scanning, background location, and offline write conflict handling need their own tested permission flows before being claimed as production features.
